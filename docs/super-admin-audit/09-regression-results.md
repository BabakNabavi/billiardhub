# رگرسیون

## روش

- هر آزمون ایستایی که شکست داشت، با «git stash» روی کد پایه هم اجرا و فهرست شکست‌ها diff شد.
- آزمون تازه هم روی کد پایه اجرا شد تا ثابت شود چیزی را می‌گیرد.
- هر مسیر تغییرکرده روی سرور محلی بی‌نشست صدا زده شد تا خطای زمان اجرا (import حلقوی) پیدا شود.

## نتیجه

| بررسی | نتیجه |
|---|---|
| شکست تازه در آزمون‌های موجود | ۵ ادعا. هر پنج شکل قدیمی کد را می‌سنجیدند و به‌روز شدند (سند ۰۸). پس از آن هیچ شکست تازه‌ای نیست. |
| `test:tournaments` | ۱۰۴ شکست، فهرست دقیقاً همان پایه |
| `test:lock` | ۱۱ شکست، همان پایه |
| `test:live` / `test:session-identity` | ۱۲ / ۱ شکست، همان پایه |
| کامپایل | ۱۷ فراخوانی `ownsClub` که کامپایلر نشان داد، همه کلید گرفتند. ۰ خطا. |
| زمان اجرا (محلی) | ۰ پاسخ ۵xx در ۱۵۰ ترکیب |
| import حلقوی | `lib/auth/ownership` ⟵ `lib/admin/permissions` ⟵ `lib/finance/db` و `lib/enforcement/server`. هیچ‌کدام `ownership` را import نمی‌کنند. بیلد و اجرا سالم‌اند. |

## خطر رفتاری که باید بدانید

پس از دیپلوی، **ادمینی که سوپر نیست** فقط به بخش‌هایی که در «دسترسی ادمین» تیک خورده دسترسی دارد. این همان رفتاری است که آن صفحه وعده می‌داد.

اگر ادمینی تا امروز بی‌آنکه بداند از همین نقص استفاده می‌کرد، مثلاً لغو رزرو بی‌کلید `bookings`، از این پس ۴۰۳ می‌گیرد و باید کلیدش داده شود. مالک پلتفرم و سوپرادمین‌ها (`['*']`) هیچ تغییری نمی‌بینند.
